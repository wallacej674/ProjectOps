# Milestone 14: Project Dashboard Unification

> Historical milestone record. Future boundaries describe this milestone at delivery; see `projectops-remaining-work-handoff.md` for the current command center.

Milestone 14 turns Project detail into a unified engineering command center. It
keeps the existing Repository Connection, CodeMap Lite, Manual Health Monitoring,
Production Readiness, and Project metadata sections, then adds a scannable
overview layer above them.

## What Was Built

- Project Command Center header with Project name, description, lifecycle
  status, repository summary, production URL summary, last updated date, primary
  next action, Edit action, and Archive action.
- Summary cards for Repository, CodeMap, Health, and Readiness.
- Deterministic recommended next actions.
- Setup progress based on actual loaded frontend state.
- In-page section navigation for Overview, Repository, CodeMap, Health,
  Readiness, and Details.
- Pure derived-state helpers for summary cards, setup steps, and next actions.
- Frontend tests for helper behavior and the unified Project detail dashboard.
- Responsive and accessible layout styles for the command-center surface.

## Dashboard Endpoint Decision

The backend has `GET /api/v1/projects/{project_id}/dashboard`, but Milestone 14
does not use it in the frontend.

Project detail already loads richer state for each section:

- Project metadata.
- `RepoIntegration`.
- Latest `RepoAnalysis` and analysis history.
- Latest `HealthCheck` and health-check history.
- `ProjectReadinessSummary` with checklist items.

The command center derives its summary from that existing state to avoid
duplicated API calls and conflicting next-step rules. The backend dashboard
endpoint remains useful for future API consumers or a later route that needs a
single compact payload.

## Summary Card Meaning

Repository:

- `Connected` means a real `RepoIntegration` exists.
- `Not connected` means no repository connection was loaded.
- Project `repo_url` metadata alone does not count as a connected repository.

CodeMap:

- `Not ready` means there is no repository connection.
- `Not run` means a repository exists but no latest analysis exists.
- `Completed` means the latest `RepoAnalysis` status is `completed`.
- `Failed` means the latest `RepoAnalysis` status is `failed`.

Health:

- `No target` means `Project.production_url` is missing.
- `Not checked` means a production URL exists but no latest health check exists.
- `Healthy`, `Unhealthy`, `Timeout`, and `Error` come directly from the latest
  `HealthCheck.status`.

Readiness:

- `Not evaluated` means readiness is missing, not started, or unavailable.
- Evaluated states come from `ProjectReadinessSummary.status`.
- Score and top gap are shown only when the readiness response provides them.

No summary card invents metrics. File counts, response time, HTTP status,
readiness score, and top gaps are shown only when loaded state contains them.

## Setup Progress Rules

Setup progress is generated by `getProjectSetupSteps`.

- Project created is always complete after Project metadata loads.
- Repository connected is complete only when `RepoIntegration` exists.
- CodeMap analysis run is complete when latest analysis completed, needs
  attention when latest analysis failed, and incomplete when missing.
- Production URL added is complete when `Project.production_url` exists.
- Manual health check run is complete when latest health is healthy, needs
  attention for unhealthy/timeout/error, and incomplete when missing.
- Readiness evaluated is complete when readiness status is not `not_started`.
- Manual readiness review appears only when manual readiness items are
  detectable. It needs attention while any manual item is `unknown`.

## Recommended Next Action Rules

Recommended actions are deterministic frontend rules, not AI output.

Priority order:

1. Attach a GitHub repository when no `RepoIntegration` exists.
2. Run or retry CodeMap Lite when repository evidence is missing or failed.
3. Add a production URL when no health-check target exists.
4. Run or review manual health checks when operational evidence is missing or
   needs attention.
5. Evaluate readiness when no readiness evaluation exists.
6. Review readiness top gaps returned by the backend.
7. Complete manual readiness review items when manual items are unknown.

The panel shows at most five actions. Each action links to a real section.

## Summary State Versus Detailed Section State

The command center summarizes loaded state; the detailed cards remain the source
for full workflows and explanations.

Examples:

- Repository summary says whether a repository is connected. The Repository
  Connection section still owns attach, replace, and remove controls.
- CodeMap summary shows latest run state. The CodeMap section still owns run
  actions, history, stack, signals, evidence, and warnings.
- Health summary shows the latest manual check. The Health section still owns
  override URL input, run action, latest result details, and history.
- Readiness summary shows advisory score/status/top gap. The Readiness section
  still owns evaluation, checklist evidence, and manual item edits.

   health check, and no readiness evaluation.

## Accessibility Notes

- The command center is an explicitly named region.
- Summary cards and next actions use text labels, not color alone.
- Section navigation is plain anchor navigation and works by keyboard.
- Long URLs and evidence-like text use wrapping styles.
- The header keeps Edit and Archive as real controls, not hidden menu items.

This is an accessibility review, not a WCAG certification.

## Known Limitations

- The command center can briefly show initial missing states while independent
  section requests are still loading, then updates when those requests resolve.
- There is no scroll-spy current-section indicator.
- The frontend does not use the backend dashboard endpoint yet.
- Readiness aggregate counts after manual item saves still depend on re-running
  or reloading readiness, matching Milestone 13 behavior.

## Future Milestone 15 Boundary

Milestone 15 can add the next real Project detail capability, such as artifacts
or recent engineering activity, by adding a new detailed section and extending
the pure command-center helpers. It should not add authentication, scheduled
monitoring, alerts, AI recommendations, security scanning, or deployment
automation unless those become explicit backend milestones first.
